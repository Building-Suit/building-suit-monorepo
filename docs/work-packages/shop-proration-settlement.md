# Proration settlement backend checkpoint

Stack: #285 → #287 → this backend draft. Worktree: cloud-only `codex/shared/shop-proration-settlement`.

## Implemented

The forward migration creates owner-scoped immutable quotes, versioned credit accounts, an append-only balanced credit ledger and immutable funding/settlement records. Pricing resolves current public terms or the existing recipient-bound private-offer handshake on the server; no client amount or bearer token is persisted. Paid basis comes from verified immutable XPay receipts, approved legacy notices with actual confirmed received amounts, or previously audited funded allocations. Trial and unverified operator grants create no prepaid cash. Historical quarterly funding can switch to supported monthly/annual terms without inventing a90day basis; active foreign-currency funding is rejected rather than converted silently.

Quote creation, admission and settlement lock resources/subscription/credit/quote in consistent order. Request identities cannot select different terms. Quotes pin full subscription state, credit version, funding evidence, currency, amounts, rounding and expiry. Only one unresolved quote is admitted. The positive path binds an immutable net-priced XPay order; the existing verified paid-observation dispatcher settles that exact quote atomically. Same-interval changes preserve renewal end; interval switches start a new full calendar term at verified settlement. Credit-only changes require explicit owner confirmation and create no fake XPay order/payment/observation. Same-plan no-ops preserve wallet version and balance. Original trial history and term entitlements stay unchanged/frozen.

The ledger enforces actual cash + prior balance + unused funded value − service allocation − final balance = recorded rounding adjustment. Balance updates must match an immutable ledger event. Stale paid quotes retain real money observations for review without granting access or credit. An abandoned provider attempt cannot be treated as unpaid unless it was never prepared or its provider state resolves unpaid. Multiple late real payments can remain in review simultaneously: the payable-order unique index covers creating/open/pending; all admission RPCs continue to block every unresolved review. Legacy creation is also blocked while a proration quote is unresolved, including rollout being disabled mid-quote.

Six independent PostgreSQL clients reached verified shared start barriers: concurrent paid deliveries produced one observation/payment/settlement/ledger/period; two credit confirmations produced one ledger/period and no provider order; competing quote requests admitted one and rejected the other safely. Workspace/token/boundary checks, changed-source lint and whitespace checks passed.

Native test interfaces for Auth claims, Storage, Vault and network/cron declarations are synthetic; no real Auth transport, Storage upload, encryption, scheduler or hosted provider readiness is claimed. Full Supabase native validation is registered in both disposable SQL runners and the GitHub payment workflow, including the same six-client race tool. `pg8.16.3` is a pinned root development dependency for this test driver.
