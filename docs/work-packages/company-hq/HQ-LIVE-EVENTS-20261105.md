## Client and server contract

`useHqLiveEvents` is one nonserializable hub per Nuxt request/app and one persistent browser connection per tab. A founder session opens native fetch-SSE `GET /api/hq/events` with `X-HQ-Access: 1`, `X-HQ-Brain: 1`, same-origin cookies and no-store. It runs only while visible and online and stops on authority loss, offline, hidden state or scope disposal. Anonymous Brain reads happen only after explicit open/manual refresh; they do not start the founder stream.

The server connects a native WebSocket to private Supabase `hq-live`. SSE names are `ready`, `brain`, `company` and `access`, with empty payloads; private note bodies, company records, JWTs and credentials never travel in these hints. Ready waits for channel/replication acknowledgment and fresh founder authorization. Each incoming coalesced burst is authorized against the current founder/session policy before forwarding. JWT expiry or revoked access invalidates authority and closes the stream. Header/loopback/dev-attestation/Host/origin/no-store gates remain. The private channel has receive-only founder policy and no client-send permission.

Read one current Brain/company snapshot on ready/reconnect to cover missed events. Later fetches follow only the matching invalidation or explicit user action. Initial/visible/online identity recovery is one-shot. Per-topic dirty queues and per-request queued flags coalesce concurrent events while retaining changes received during an active read/decision. Stale response epochs, cancellation, idempotent decision keys and auth/offline cleanup remain. A one-shot bounded backoff reconnects a failed stream; it is not a recurring data-read timer. Protocol WebSocket/SSE keepalives run no Drive or database query.
