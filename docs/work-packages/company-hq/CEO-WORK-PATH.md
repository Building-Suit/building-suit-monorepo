## Implemented contract

`create_task` accepts `sourceMessageId` only through the founder action. The source must be one unanswered founder-to-CEO message, with a unique immutable task association. The server retains its exact text and identity digest. Creating the proposal grants no execution authority. The normal `approve_task` and later `authorize_workflow` remain separate founder actions, and both revalidate the source. Linked work cannot use public tools, daily execution, legacy bridge task updates or a bridge reply that bypasses its active runner.

The website exposes this sequence explicitly. The shared task brief starts empty; the private message is shown separately with a sharing notice. Only the reviewed task brief goes to Noah, Iris and Maya. `workflowAssignment` adds the original message to Steve's final reply stage only. File selection accepts exact Drive/Docs links or IDs and sends a normalized, distinct 16-file map to the existing authorization endpoint. An interrupted save retains its form and idempotency key. Session changes and disposal invalidate stale confirmation intent and private drafts.

`HqCeoDispatcher` owns one genuine `HqStore` connection and constructs its runner against that same connection. `dispatchTask(id)` and `dispatchNext()` each attempt at most one approved, linked, non-daily assignment. Selection is bounded at 1,000 retained tasks and ordered by creation time/ID. It installs no polling loop, startup hook, timer, provider transport or HTTP execution endpoint. The ordinary host bootstrap exposes these methods with immutable disabled defaults and the closed production executor. Invoking them does not create a credential or prove a host is durable. Memory stores are useful only for synthetic tests; real activation still requires the existing verified persistent-file bootstrap and host evidence.

The dispatcher refuses unfinished attempts, blocked work that needs another inference, and unresolved provider outcomes. Completed checkpoints can resume without repeating their model calls; all four checkpoints may finish pending delivery after restart. Claim-time and pre-reservation checks repeat under the SQLite writer lock, so an intervening process cannot exploit an earlier stale preflight read. A completed provider operation must have a unique matching attempt and checkpoint whose result digest covers identity, output, sources and review. A new context/reservation cannot bypass a lost checkpoint. A mismatch or unknown outcome requires reconciliation; this implementation neither reconstructs missing provider output nor refunds/resends it. Usage remains evidence rather than a funding authority.

The existing outbox now binds its deterministic key to the source message. One transaction validates the still-current source, appends the CEO reply with `replyTo`/`taskId`, marks exactly that original message answered, and completes the task/outbox. A failed transaction preserves the previous state. Repeated delivery does not duplicate the reply. Cancellation fences unfinished runs; closing a dispatcher aborts its active call and waits for bounded settlement before closing SQLite. It does not close a live connection beneath an awaiting runner.

## Synthetic browser fixture boundary

`scripts/synthetic-ceo-worker.mjs` is imported only by the browser test server with an explicit CLI flag. It accepts only that test server's newly created temporary SQLite path, a single synthetic source/title marker and the exact synthetic 16-file scope. Its four deterministic adapter outputs explicitly identify themselves as synthetic. It performs one dispatch, has a five-minute lifetime and does not retry blocked work. No default application route or startup imports it, and it contains no provider/Drive transport. The browser child environment forces local storage, false hosting/backend flags and empty Supabase configuration even if the surrounding shell has other settings. Shutdown settles the worker before removing the disposable database.

This fixture proves the website-to-store-to-dispatcher-to-outbox connection locally. It does not qualify a real model, account, Brain credential, VM or deployment. Synthetic completion leaves the page's live-runtime status explicitly unavailable.
