## Implemented behavior

The state projection contains Steve / AG-CEO-001, Maya / AG-HR-001, Noah / AG-HR-002 and Iris / AG-HR-003, with explicit qualification and unactivated-runtime labels. The legacy `ceo` / `hr` identities, historical HR-001 record, bridge credentials and founder-only CEO conversation remain compatible. The complete shared office composition is unchanged. The workforce is visible through authorized state and its Brain notes; no extra rooms or direct employee conversations were added.

`hqRunner.ts` executes the ordered research → evaluate → consolidate → reply stages through injected trusted adapters. Each invocation gets a new context, its current profile, current playbook and approved bootstrap/policy context. Iris receives Noah's artifact and fixed criteria without Noah's conversation state. Host-attested role/context isolation and an accepted review bound to the exact candidate digest are required before Maya can proceed. Roles may use the same underlying provider principal; independent invocation and role identity are required, not a claim that separate API accounts improve review quality.

Execution uses the existing dedicated SQLite `HqStore`. The new server-only synchronous transaction method uses `BEGIN IMMEDIATE`, the existing size cap and rollback. Run claims, lease generation, stage checkpoints, current task approval/cancellation and deterministic outbox writes share that same workspace document. Old documents without workflow fields remain valid. No SQLite table or hosted SQL migration is needed.

One 60-second lease is granted per task, or per dedicated company database/local date for daily work. Each stage is bounded to 30 seconds, renews its lease before starting and checks persistent cancellation every 100 ms. Stale generations cannot save results. At most two inference attempts per stage/eight per run are permitted; every dispatched reservation/context is retained. A crash between model execution and checkpoint can repeat inference, subject to a new atomic allowance reservation. Exactly-once model computation is **not** claimed.

All 16 approved Brain files are freshly authorized/read before each stage and again before delivery. Missing files, stale timestamps, denied access, changed revisions and incomplete bootstrap maps block continuation. A policy revision change after a checkpoint requires cancellation and a newly approved assignment; retries do not quietly accept an old review under new policy. File IDs, revisions, content, input, output, tool evidence, review and safe failure codes remain in the private workspace. Adapter error strings are not logged. The existing 8 MB workspace cap fails closed; bounded evidence retention/export needs an authorized operational plan before sustained daily use.

Only explicitly approved `public.search` and `public.read` calls are supported. The founder must approve exact public query/URL strings (up to eight); the model cannot append private Brain content to public queries. Each stage allows up to six calls, each capped at 20,000 response characters. The trusted research adapter must reject private/local network URLs, redirects into private networks, credentials and effects. No public network adapter is installed here. A swallowed tool denial, unfinished tool call or unobserved source citation blocks the checkpoint. Brain writes, package installation, arbitrary code execution, staffing changes and external messages are absent from the tool broker.

Authentication, provider/data scope, zero incremental cost, positive remaining allowance and an atomic reservation are checked before each model invocation. Current authorization and cancellation are checked before and after asynchronous work. Delivery requires fresh Brain and valid model authorization, but does not consume another model allowance. No paid fallback or credential creation is implemented.

## Founder contract and host integration

The existing authenticated, same-origin `POST /api/hq/action` accepts `authorize_workflow` only for an already founder-approved queued task. It binds immutable explicit scope; changing it requires cancelling and proposing another task. The request includes the usual `idempotencyKey`, task `id`, `allowedTools`, `publicInputs`, `brainFiles`, `daily` and `timezoneConfirmed`.

`brainFiles` requires exact, distinct IDs for `AG-CEO-001`, `AG-HR-001`, `AG-HR-002`, `AG-HR-003`, `playbook`, `bootstrap`, `charter`, `workingAgreement`, `registry`, `organization`, `hrCharter`, `workforceSkill`, `home`, `soul`, `milestones`, and `mode`. This explicit approved map is intentional: current Drive inspection found older duplicate Recruiter/Evaluator filenames using Nora/Adam, while the latest requested profiles and registry use Noah/Iris. Do not choose a document by filename or version number alone. Resolve the selected mode and relevant policy references against the current founder request; missing relevant notes block activation. Live authorization never follows instructions in a retrieved source to expand the map.

The authorization endpoint stores configuration only. It neither creates a worker nor enables a timer. Normal bridge task updates cannot bypass the bounded runner on a workflow-managed task. The founder can cancel through the existing UI/API at any point before completion. External caller AbortSignals stop an attempt; persistent founder cancellation terminates the task and fences every unfinished run.

A subsequently authorized host can construct `HqRunner` with the dedicated `HqStore`, verified readiness, an `ExecutorAdapter`, `BrainAdapter` and optional read-only `ToolAdapter`, then call `run(taskId)` or `tick()`. Defaults are disabled. No Nitro startup hook, public runner endpoint, cron, hosted scheduler, provider client or deployment configuration is installed. A future host must implement trusted adapter isolation, fresh connector authorization, private-data scope, atomic included-allowance reservations and provider idempotency/reconciliation where available. The adapter identity envelope must be constructed by the trusted host, never accepted from model-authored JSON.

The runner deliberately does not accept `HqRemoteStore`: it requires synchronous atomic workspace transactions. The existing guarded remote adapter is preserved for manual HQ actions. Hosted runner activation needs a reviewed transactional remote implementation or verified dedicated persistent SQLite host, with a genuine end-to-end trial. Do not cast a remote store to bypass the type boundary or enable a second scheduler.

## Schedule and delivery semantics

08:00 in `Africa/Cairo` remains a documented assumption, not a confirmed founder timezone. The authorization API requires explicit `timezoneConfirmed: true` for daily work. `tick()` checks the IANA timezone (including DST), runs only at/after 08:00, rejects multiple approved standing schedules, and claims one current-local-date run. It is a callable scheduler integration point, **not an activated schedule**. Historical dates are not silently backfilled. Host outage/missed-day detection and founder notification still require the actual scheduler integration; no past-day delivery is claimed.

08:00 starts work. It does not promise a finished report at that time. The full stage timestamps and local date are recorded. The host must report a late/missed invocation accurately.

Steve's report is delivered to the existing private HQ CEO inbox. Outbox preparation is durable; inbox message, deterministic receipt, event, task result and completed run are committed atomically together. A failed commit leaves the pending outbox and committed stages available for retry. A completed retry reuses the original outcome without another message or model call. This guarantees inbox persistence in the same SQLite database, not an email/push/chat notification or proof the founder read the report. External delivery and Brain writes are deliberately not attempted; any future adapter needs its own idempotent outbox and uncertain-outcome reconciliation.
