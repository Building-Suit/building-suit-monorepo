## Implemented independent lifecycle model

`patientReminderLifecycle.ts` separates immutable scheduled occurrence/source identity, synthetic notification evidence and explicitly patient-reported/unverified adherence references. Missing, unknown, failed or expired notification state never implies a missed dose or verified administration. There is no medical amount, compensation or treatment recommendation in an event or transition.

A fixture snapshot must bind the same scope, finite current observation/lease, monotonic source revision, an unchanged same-revision fingerprint and explicit per-event expiry. No default medical grace period is invented. New future event IDs yield one preview intent; accepted/unknown/failed outcomes subsequently request inspection rather than resend. Elapsed newly observed events produce no catch-up intent. Stop/amend/expiry/report retirement retains terminal IDs and historical source/report references, cancels only the first owned obsolete preview intent and cannot be undone by reconnect or a newer snapshot containing an old ID. A new prescription version has its own source-bound ID. Technical512-entry/history bounds fail closed rather than evicting terminal IDs into duplicate scheduling.

Synthetic observation versions and report-reference versions are independent. Report corrections append provenance with patientReported=true/clinicallyVerified=false, preserving the earlier claim without resurrecting a retired reminder. Missing/conflicting report history is rejected rather than invented. A delayed old presentation is recorded as late/invalid and cannot enable action; replay of a legitimately earlier presentation after stop preserves that historical observation while current action remains suppressed. The input checkpoint is immutable, and a Node JSON roundtrip preserves issued IDs/terminal state for protocol tests.

This is plain memory state, not approved private device persistence, durable server storage or a native notification adapter. Attempt keys are internal fixture trace identifiers, not approved OS payloads/channel identifiers. A future approved integration must enforce actual current identity/relationship/consent/source/ownership and appropriate secure persistence, notify withdrawal/offline/background and honour server cancellation. No immediate offline remote-erasure/cancellation or delivery guarantee is claimed. All actual patient/native/provider/live-data implementation remains held.
