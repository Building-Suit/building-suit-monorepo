## Concrete requirement and source gap

Canonical C01 requires redacted operational signals for authorization, outbox/reminders, payment reconciliation, storage and recovery. Its criterion-specific contract has `external_evidence_required: false`; C02 separately requires accountable human review. A missing incident owner is not a reason to leave the independent signal implementation unbuilt.

Existing `operationsReadiness.ts` validates subscriber-scoped reconciliation counts and explicitly unavailable recovery/telemetry state. `messageOutbox.ts` validates bounded authorized message states, preserving sent/delivered/unknown distinctions. Neither provides a redacted file-service failure observation point. The document and payment-evidence handlers sanitize HTTP errors but had no way for an owned synthetic executor to observe authorization/availability faults without inspecting requests or raw exceptions.

Both actual handlers now accept an optional observer receiving only one of six fixed strings: session rejection, access rejection or unavailability, separately for administrative documents and payment evidence. The status comes from the existing sanitized response. An availability observation is not proof of a storage outage, breach, rejected payment or settlement outcome. Successful delivery and input/conflict failures do not produce these failure signals.

The supplied buffer contains six bounded counters, an explicit saturation flag and a reset operation. Snapshots are immutable and contain no user/tenant/session/patient identifiers, file names/paths, timestamps, amounts, clinical text, credentials or arbitrary error values. Counters cap at 65,535 solely to bound diagnostics; that number is not an incident threshold, quota or performance objective. Instances do not share state. Unknown input is rejected without coercion. No log writer, persistence, outbound sink, request header, environment switch or telemetry endpoint is added.

Runtime entrypoints still construct handlers with two arguments, leaving observation disabled. A trusted synthetic caller must explicitly supply its private buffer. No client can select a sink or read another caller's buffer. Observation never grants access or affects HTTP responses; synchronous errors and rejected promises are contained, stalled observers are not awaited, and no observation failure retries a write or deletes possibly committed bytes. Existing session/grant checks before and after file I/O remain intact.
