## Contract and decisions

The new reception command is synthetic-preview only and requires current appointments.write, queue.manage and patients.read in the clinic after the practice calendar lock. Active patient relationship, Auth session and actor are rechecked before exact receipt replay. All exceptions require a reason; writes use Read Committed, expected row version and session-bound idempotency. Important mutations, audit and receipts are one transaction.

- late_check_in: booked -> checked_in only after the start on the captured clinic's current day. A second request cannot add another queue entry.
- reverse_no_show: no_show -> booked, preserving original captured appointment clocks/type and missed-visit history. Appointment and effective waitlist hold capacity must be free; reversal never overrides buffered capacity.
- queue_exit: checked_in -> cancelled, retaining arrival/history. In-progress/completed visits cannot use this exception.
- move_to_end: checked_in -> checked_in with a new server-assigned administrative queue position, preserved arrival time, actor/reason and before/after positions in immutable history. It assigns no clinical priority.
- walk_in: explicit existing patient plus an available same-day slot -> ordinary authorized booking and check-in atomically. It uses captured schedule/location/type versions and private nested keys, never contact equality, identity creation/merge or an overbooking override. Reason, booking, check-in and reception history remain stored.

Normal booking, no-show, check-in, rescheduling and administrative visit transitions retain their existing contracts/receipts. New reception permissions do not grant clinical draft/sign/release authority. Doctor and delegated secretary permissions stay distinct. Legacy queue positions remain zero and sort by original arrival/id; new arrivals receive a position after the existing queue under the same calendar lock. Reordering occurs on the complete authoritative queue before pagination. No applied migration is rewritten or data erased.

The existing BsPracticeAppointmentsPage supplies finite optional walk-in configuration, a pinned reason-required editor and administrative queue policy. Product adapters own commands, validation and translated action/history projections. Shared record-action controllers retain pending/dirty/focus/error behavior. No Suit-local presentation layer or new route was added. Generated schema types include the new RPC and queue position.
