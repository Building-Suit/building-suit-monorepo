## Implemented independent protocol

`patientCaregiverProtocol.ts` has no imports, network, storage, native package or route. Its fixture ledger records an immutable named grantor, independent recipient account, dependent, doctor/practice relationship, limited actions, policy and authority references, validity and versions. It refuses extra fields, actual legal approval, duplicate actions/grants, invalid clocks and self-delegation. No birthday threshold, legal status, contact match or user metadata can create authority. Every stored record is explicitly synthetic with legal approval false; this is a protocol fixture, never an Auth authorization service.

Withdrawal requires the fixture grantor and exact version and appends provenance without mutating the original or action history. Lookup requires an already-known grant ID and exact scope; it cannot enumerate siblings or another relationship. Pending reminder previews recheck current grant/version/expiry; withdrawal suppresses them. No notification is scheduled or sent.

The memory projection reader checks grants before and after an awaited read, binding account/session/dependent/doctor/practice/relationship, grant ID/version/expiry and request generation. It rejects revoked, expired, foreign and out-of-order responses, clears retained data before revalidation and fails closed on clock rollback/invalid time. The embedding application would have to invoke clear on background/offline/revocation notification and revalidate every operation; no patient application is integrated and no offline revocation/remote erasure guarantee is claimed. Live/cached access and actual notification suppression are not qualified by this harness.
