## Contract and decisions

Synthetic-preview only. Channels, purpose consents and patient-specific guardian relationships are separate from Auth identity. Phone/email equality is not a unique key, account lookup, patient merge or relationship grant. An explicitly selected patient and recipient scope are required. Each new channel has no consent rows, including marketing. Destination changes require a new channel and explicit new consent; existing destination records are immutable through the API and revocation retains history.

Contacts and relationships apply to the selected practice-patient, across that practice’s clinics, subject to current patients.read/write at the requesting active clinic. The clinic recorded on creation is provenance, not a silent grant for another practice. Explicit guardian review scopes communication purposes for that same practice-patient and has a bounded expiry. A stored practice owner records a synthetic review; secretarial write permission cannot substitute for that review. Pending entry alone grants no authority. Review records expose synthetic_review_only/live_authority false and never establish legal/minor, clinical, login or outreach approval. M7 evidence remains open.

Consent grant requires explicit purpose, source reference and entered clinic-local source day/minute with the captured clinic version. The server rejects invalid/DST-ambiguous/nonexistent/future source clocks and stores the precise source instant separately from actor-attributed server recorded_at. Guardian review requires explicit purpose scope, source and future expiry within365 days. No purposes, checkbox permission, recipient relationship, source clock or expiry is guessed. A current consent captures contact and guardian versions; re-review/renewal requires new explicit consent. A prepared intent captures all those exact versions and purpose. Revocation, expiry, patient/clinic archival, relationship scope or version changes deny subsequent eligibility; re-approval cannot silently revive an older captured intent.

Mutations use Read Committed, the practice calendar lock, current membership/grant row locks, patient/archive checks, expected versions and actor/session-bound exact receipts. Current authority is rechecked after waits and before receipt replay. Important writes, immutable finite history, redacted administrative audit and receipt commit atomically. Direct table/sequence access and ambient service-client mutation are denied. Archived patient history remains readable to current authorized readers and revocation remains available as a reduction; new channels, consents and reviews are blocked. Patient/contact/guardian identity and previous source facts are preserved.

The private eligibility policy and public scoped prepared-intent check send nothing and return no dispatch destination. M3-005 verifies capture -> consent/guardian change -> authoritative policy denial. The original scenario involving a persisted queued message and actual dispatch suppression remains pending M3-006; this feature does not falsely claim an outbox exists yet. M3-007 provider evidence remains separately required before any external adapter/outreach.

BsPatientContactPreferencesPage owns complete presentation, controlled finite record forms, BsDataTable and history. Doctor owns scope, decoding, source/clock validation, repository/controller and semantic commands. Shared record-action behavior retains pending/dirty/focus protection. Patient/scope/session changes and denial clear private projections and reject stale async results; uncertain retries retain the exact intent. The current shared catalogue had public-contact and analytics-consent pages, neither matching this patient-specific workflow, so a dedicated canonical template was added with explicit exports/route registration/catalogue. No Suit-local component/CSS or provider query is introduced.
