## Implemented contract

`doctor_outbox_command` persists a purpose-specific captured contact/consent/guardian envelope and explicit immutable consent ID. Templates are versioned purpose names with an empty parameter object; arbitrary bodies, attachments, clinical values and destinations cannot enter the outbox. The channel destination stays in the separately authorized contact store. Actor/session-bound idempotency receipts, optimistic versions, current membership row locks and the same practice lock used by consent commands serialize important transitions. No worker, cron, callback endpoint or ambient service-role execution is granted.

`enqueue` → `claim` → `accept` → `acknowledge` → `deliver` are explicit separate transactions. Claim supplies an unpredictable lease token. `accept` is a local synthetic transport operation, rechecking captured consent, guardian purpose/version/expiry, patient/clinic activity and expiry after lock waits. Acceptance is stored in a private durable table separately from acknowledgement and delivery. A crash after acceptance leaves a committed acceptance with no acknowledgement. Expired claims first become unknown; reconciliation of a known acceptance only becomes sent. An absent acceptance stays unknown and cannot retry. Delivery requires an additional explicit authorized synthetic receipt; sent never implies delivered. Late consent withdrawal cannot erase a prior transport acceptance.

Only a definite rejection with no acceptance permits retry, with 30/60-second backoff and three attempts maximum. Timeout is ambiguous and never treated as rejection. Failed/unknown messages and fixed redacted reasons remain visible through a bounded patient/location status projection. Direct table access, foreign doctor access, missing write permission and forged claim/delivery capability are denied. History and audit omit destinations, bodies and clinical content. The browser status route is read-only and clears private state on patient, session, context and permission changes.

The linked M3-005 scenario now persists a queued intent, withdraws consent and checks suppression with no acceptance row. A separate transaction scenario withdraws while dispatch waits for the practice lock. Another expires guardian review during that wait. These test synthetic dispatch, not real delivery or qualified guardian authority.
