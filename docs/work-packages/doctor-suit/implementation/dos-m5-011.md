## Concrete server and device design awaiting approvals

Propose an append-only installation registry scoped to patient/account/relationship with a monotonically versioned registry epoch. Reinstallation creates a new ID and revokes the previous registration; never infer identity from contacts or a device identifier. Current account/session/relationship/grant checks must precede every read, mutation and receipt response. Expired/revoked registrations cannot acquire or renew ownership.

Propose durable exact-intent action receipts unique within actor/patient/relationship/key, optimistic per-event versions and append-only correction references. Receipt acceptance and acknowledgement are separate; response loss requires lookup of the original key, never a new action. An accepted correction remains authoritative when an older acknowledgement arrives. Conflicts retain both proposals until an explicit authorized resolution; device timestamps are unverified provenance, not a conflict winner.

Propose a unique per-event ownership row with atomic compare-and-set against registry epoch, event/source version and current consent. Persist attempt issuance, unknown scheduling outcome, cancellation request and independently observed cancellation confirmation separately. No ownership transfer may create another attempt until the prior outcome is resolved under an approved channel policy. Terminal retirement prevents source rollback from reviving events. This is a design proposal, not a deployed schema or durable/crash proof. Offline revocation cannot promise immediate erasure or cancellation on an unreachable device.

Required future disposable SQL cases include concurrent acquisition, action replay after response loss, changed-intent rejection, old-ack/new-correction ordering, stale registry CAS, revoked/reinstalled/foreign installations, fresh caregiver/consent withdrawal, RLS read/write isolation and cancellation-before-handoff.
