## Implemented independent memory transactions

`patientReportPreview.ts` registers only an immutable M5-006 event/source ID, named patient/relationship/version and original occurrence; exact shapes reject private/dose/regimen payloads. The fixture admission separately names account/session/dependent/relationship/version, patient/caregiver reporter and limited read/report/correct/snooze permissions. It never matches contacts, grants a real Auth account authority, creates a legal caregiver relationship or marks a statement clinically verified.

Taken/skip are patient-reported claims, not confirmed administration or clinical outcomes. Audit retains actor, original session, source/version, original schedule, separately reported patient time, fixture server time, action/version and correction reason/reference. Corrections preserve old entries and require an existing report; they never rewrite clinical instructions or automatically recreate a reminder. Snooze retains original event/schedule and changes only a notification-preview timestamp. It requires an explicit unreviewed ceiling, known next occurrence or explicitly-none state and active source; unknown policy/next event and a stopped source yield no snooze. The strict-before-next proposal is a fixture conflict policy awaiting clinician review, not an approved clinical cutoff.

Command input is copied/frozen before callbacks so a caller cannot mutate the operation after its intent is bound. Command namespace binds account/dependent/relationship/key and a canonical exact-intent fingerprint; reorder of object keys does not change intent. Accepted and conflict/error acknowledgements are retained. Exact retries, including a newly admitted session of the same actor, return the original receipt without duplicate history or notification action; changed intent under an existing key is rejected. Current admission is still required before replay, so withdrawal/expiry cannot expose an old acknowledgement. Technical bounds128 events/512 receipts fail closed without evicting keys into accidental duplicate writes. There is no database/persistence/offline queue; actual crash durability requires a future approved atomic server implementation and cannot be claimed from this memory model.

A focused concurrent-snooze regression actually fails before the fix (9pass/1fail initial suite): a nested transaction during eligibility changed the version after the first comparison. Recheck both expected version and any receipt created during the callback before committing. Fresh admission is also checked after policy evaluation, including policy failure after withdrawal, so no protected receipt or fallback write escapes. The complete13-case rerun passes.
