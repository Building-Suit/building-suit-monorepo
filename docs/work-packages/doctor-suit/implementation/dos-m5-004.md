## Implemented projection and privacy contract

`patientReleasedTimeline.ts` reuses the canonical M2 `clinicalReleased` decoder rather than copying its medical payload validation. The pure input envelope binds an explicitly synthetic patient portal, account/session/dependent, finite admission expiry, named doctor/practice/location relationships and exact versions. It rejects foreign/revoked relationships/releases, private fields, unreviewed result payloads, invented clinical/signature authority, duplicates, invalid ordering, expired sources and inconsistent page populations. Contacts cannot join records and a doctor portal never reaches the adapter.

Output contains only timeline metadata/counts and explicit immutable release/version/revision/hash links, grouped by relationship/doctor/practice/location. It contains no private notes/intake, patient-name matching, prescription/result/document payload or storage URL. The hash is preserved source provenance; this summary projection does not independently verify original clinical bytes. Two doctors' releases remain separate records and grant no reciprocal doctor access. Bounded20-row pages replace rather than accumulate; empty/out-of-range pages and corrected provenance are explicit.

The memory reader fences late requests by full scope/generation, clears before each request or denial, and expires at the earliest admission/release deadline. Scope/relationship changes, invalid/rolled-back clocks and explicit clear remove the retained projection. A future approved integration must notify withdrawal/background/offline and perform fresh server authorization per read; this fixture is not an endpoint, native cache policy or remote-erasure guarantee.
