# DOS-M2-002 — synthetic encounter foundation

This task introduces practice-owned encounters with separate patient relationship, originating location/timezone and responsible owner attribution. Create/save/start are atomic, current-session authorized commands with actor-scoped idempotency, expected-version conflicts, immutable revision hashes and safe attributed events. Independent expiring fixture rights are required in addition to existing administrative rights; migrations seed no access. No professional signature or live prescribing authority is created.

The storage foundation reserves immutable note, release and recipient records for dependent tasks, but this checkpoint exposes only encounter command/workspace/detail RPCs. Intake, note content, prescriptions, orders and results remain unavailable until their task migrations add the corresponding validators. Finalization, amendment, release, recipient delivery and export are not exposed by this command checkpoint. Typed client contracts reserve those later shapes; they cannot override server availability.

The client controller fences delayed responses by environment, verified user/SID, practice, location, query generation and selected record. Changing scope clears private state; uncertain identical writes retain their idempotency key. Direct raw table reads/writes are revoked, including service adapter writes to immutable versions.

Validation is recorded in the PR with exact command outcomes. SQL fixtures use rolled-back synthetic accounts and explicit test-only capability bindings. The disposable runner retains existing suites, races and isolated restore checks, and generates public types from the migrated database. Its minimal Auth/Storage scaffolds do not prove actual Supabase service or private-byte behavior. The complete editor and rendered browser acceptance will be connected on the M2 integration task; this backend checkpoint alone is not complete M2 acceptance. Qualified clinical review remains OPEN.
