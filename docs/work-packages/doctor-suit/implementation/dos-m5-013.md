`patientAccessiblePreview.ts` reuses the strict M5-005 prescription/release projection. It preserves the complete entered prescription instruction string (including mixed Arabic/English, newlines, combining characters and literal markup-like text), exact decimal amount string and each original segment's dates, timezone, cadence fields and instruction. Deterministic semantic reading order is medicine/strength/form, entered amount/unit/route, dates/full instructions, then every segment in source order. Locale changes labels and LTR/RTL direction, never medical values or segment order. No abbreviation, dose conversion, inferred schedule, missed-dose conclusion, compensation or treatment advice is generated. This is a content model, not a rendered UI or verified clinical source.

Connection online/offline/unknown and notification unknown/unsupported/denied/permission-reported states are separate and bilingual. Permission never confirms delivery; reminders are not guaranteed. Last successful read is an explicit unverified observation timestamp, not an invented current sync or delivery status; a never-synced state remains null. Future/invalid timestamps are rejected. A different account/session/dependent scope cannot expose the prior scope's refresh metadata.

No private persistent cache is approved or implemented. Offline/unknown connection, background, revocation, expiry, wrong scope or invalid/withdrawn release produces no private instruction content. The projection has no persistence, notification or automatic action adapter. Future integration must invalidate retained rendered values and lifecycle subscriptions immediately on observed scope/offline/background/withdrawal changes; a pure function does not erase another consumer's copied data or guarantee instant remote revocation on an unreachable device.
