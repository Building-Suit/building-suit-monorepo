## Contract

`doctor_fulfillment_command` binds one operational record to an exact issued immutable clinical version, encounter, patient relationship, clinic and lab/imaging/referral order. One order in one encounter has at most one tracking record across source revisions. Draft/unissued, mismatched patient/clinic/version, withdrawn or cancelled requests are denied; the captured source remains immutable. Active request authority is rechecked before arrangement/receipt. Cancellation is a recorded operational reduction, never a clinical cancellation.

Current patients.read/write grants authorize operational tracking; documents.read additionally gates receipt and document choices/metadata. Each actor/session-bound exact command has optimistic versioning, a practice lock, fresh membership locks and an atomic receipt/history/audit write. Source references are bounded. Direct table access and ambient service execution are denied. A synthetic review/sign fixture is restricted to the owned browser fixture so it can issue an actual source request; administrative staff still acquire no clinical review/sign authority.

Receipt links a specific existing document version for the same practice/patient to that exact tracked request. The caller must explicitly select the request and document and enter source and received instants with offsets; source/received/server-recorded times remain distinct. Wrong-patient files are rejected. Receipt state is always unreviewed in this workflow and never writes a clinical version, result interpretation, review, release, notification or partner-API fact. M2 remains authoritative for actual clinical review and release. Exact retries append one receipt event; received/cancelled tracking cannot silently reopen.

The complete shared BsFulfillmentTrackingPage owns presentation, table and controlled record dialogs. Doctor owns finite DTO decoding, authorized source queries and commands. Request choices bind encounter/version/order together; a reused order UUID in another encounter cannot silently select a different source. Patient-only readers see operational status with document metadata redacted. Queries are bounded (20 rows; latest 100 issued-request/document choices). Patient/session/scope changes abort reads and clear source projections/drafts; concurrent page responses cannot overwrite newer data. Uncertain writes keep the same exact key and fields; denied writes discard patient/source state. Synthetic transport and clinical/legal/provider gates remain unchanged.
