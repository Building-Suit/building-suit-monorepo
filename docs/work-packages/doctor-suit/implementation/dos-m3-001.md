## Contract

Consultation types are practice-owned, append-only revisions with explicit entered name, duration, before/after buffers, allowed clinics and active status. A booking captures the complete reviewed type/version snapshot. Changing or deactivating configuration cannot rewrite an existing booking. Rescheduling uses the captured duration/buffers/location permissions, not the latest type configuration.

Doctor capacity remains exactly one concurrent commitment across all clinics, preserving the existing M1 invariant. Group/parallel consultations and capacity overrides are unsupported and explicitly denied, including for owners. No override path exists that could omit a permitted actor/reason. Legacy schedule-duration booking remains an explicit compatible choice.

One authoritative interval function handles typed and legacy availability, booking and rescheduling. A database exclusion constraint includes the before/after buffers for every appointment path. All buffers must fit inside effective opening windows. Clinic timezones remain checked by the existing IANA write trigger; private location-backed clock conversion reuses the same DST algorithm without rescanning the timezone catalogue for every offered minute. The checked clock entry point retains its original semantics and the trusted core is not executable by API roles. IANA zones and existing explicit exceptions remain authoritative; missing/folded clocks and elapsed-time discontinuities are rejected. CAS, session-bound request keys, post-lock authority and exact receipt replay preserve concurrent integrity. Administrative-candidate mode cannot access the new operations RPCs; no clinical/provider authority is inferred.

The shared BsConsultationTypesPage owns the table and record editor. Doctor owns typed configuration/query/commands and bilingual copy. The existing shared appointment page accepts optional typed choices; other consumers retain their existing path. No new palette, local Vue component or app styling layer was added.
