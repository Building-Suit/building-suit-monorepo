# DOS-M1-017 — scoped administrative and personal audit

Child of PR361 `36797466dc3980d3d2e2c70b3e0c980318e7fc15`. The parent follow-up was merged with history preserved into the isolated audit branch before publication. Planning PR345 remains byte-for-byte unchanged; no Automation operation or hosted provider change is performed.

## Read and authority contract

`/audit` shows five safe fields: event ID, verified actor UID, administrative event type, opaque record identity and stored timestamp, presented explicitly in UTC. Owners see their whole practice, including archived working locations. A delegated reader needs the new explicit `audit.read` capability for the selected active clinic. Each clinic represented in a cross-clinic event must independently grant audit access and the associated patient/document/appointment/location permission. Practice-wide ownership, invitation and permission events remain owner-only. Existing delegated memberships receive no new grant automatically; the grant catalogue and both server/client bounded validators include the new capability.

`/account-activity` reads only the current product account's personal-setting events. It neither inherits practice ownership nor exposes another member's account activity. Both routes require a verified current provider session. Raw audit RLS stays owner-only, with a restrictive ownership guard; client mutation privileges remain denied, reinforced by restrictive insert/update/delete guards. The audit projection never serializes credentials, personal names/contact values, private file paths, invitation tokens, free-text reasons or original event details. Search covers only the safe action/identity fields, treats wildcard characters literally, and bounds query length and page size. PostgreSQL bigint event IDs serialize as text, preserving values beyond JavaScript precision; personal audit IDs remain opaque UUIDs.

Actual administrative commands continue to create their existing attributed events. Document access is accurately labeled **requested**, without claiming that bytes reached the user. Existing correction, immutable document versions, linked appointment/location histories and archive blockers are preserved. No deletion, clinical bulk export, erasure or retention period is invented. Those controls remain unavailable, and real-data governance stays open.

## Ownership and lifecycle

Shared `BsAuditHistoryPage` supplies optional controlled search/paging and a safe summary mode. Its existing full-details consumer retains its default contract. The shared auth shell and audit root bound their inline size so personal activity tables scroll within a narrow viewport. Doctor adapters own every query, permission, scope and event label; no app-local presentation is added. Two routes are appended to the canonical inventory; the strict boundary has 104 templates and no local components.

Private result state is cleared on account/SID, practice, clinic or grant revision changes. Independent abort/generation checks reject captured old responses and replaced searches. Foreground authority reconciliation does not wait for a delayed audit data response, so fresh revocation can clear that response before it completes. Empty, loading, denied, invalid-query and retry states remain explicit. Owner audit remains available when all owned clinics have been archived; the server still resolves ownership from the current verified identity.
