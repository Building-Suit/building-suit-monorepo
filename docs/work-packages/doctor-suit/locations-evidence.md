# DOS-M1-008: working locations and explicit context

This change follows the immutable planning-v0.4 DOS-M1-008 contract from PR345 head `4ca7110f4d6efa828e0b41213e5c059bf02ba9db`. Parent PR353 supplies the verified session and doctor-owned practice setup. Automation remains inactive; no plan import, hosted migration, deployment, provider connection or main promotion is performed.

A practice has one stored doctor owner across its working locations. Location commands update only name, named IANA timezone, bounded contact phone/address and archival/version fields. They preserve rows and create attributed audit events. Requests use actor-bound idempotency receipts, optimistic versions and a practice transaction lock. Create requires stored ownership; an explicit existing-location management grant permits only that location's update/archive. Every command rechecks the verified session and current stored permissions. Clients have no direct DML grant. Owner settings remain usable after the last active location is archived, without creating an operational context.

The settings directory is bounded, paginated, literally searched and filtered per authorized location. Its contact fields require location-settings permission. Minimal operational context contains the owning doctor/practice/location labels, named timezone, server-resolved doctor/secretary portal and administrative capabilities; it exposes no location contact settings or clinical capability. One secretary can receive different grants from two doctors. Forged IDs, editable metadata, stale grant versions, revoked membership and anonymous callers cannot establish authority.

The app owns configuration, validation, typed RPC adapters and per-Nuxt-app state. Shared UI owns the complete location template, BsDataTable, shell selector/banner and record-action dialogs. Shared UX gains an explicit reset operation that discards old pending success/failure effects; existing consumers retain their defaults. Multiple contexts require an explicit choice. A cookie preference is untrusted, verified against the latest authorized options and bound to user/session. Switching immediately aborts private reads and clears rows, search/paging, local drafts and dialogs. Scope keys include product, environment, user, session, portal, practice, location and grant/location revisions. Stale responses cannot restore previous data or close a newer dialog. Revocation/archive removes the previous context without silently selecting another doctor.
