This work follows DOS-M1-009/010 in PR355. Its inherited committed tip is `fa4732cfe8214ace8d55cfa689b1131a8b8958a5`; the parent's verified local auth/context-recovery repair is included, with exact-head GitHub checks tracked on PR355. Immutable planning remains PR345 head `4ca7110f4d6efa828e0b41213e5c059bf02ba9db`. The approved synthetic dataset decision is DOS-M1-D003. Real-data retention/legal review remains a separate M7 gate.

Patient identity, doctor-practice relationship and future encounter remain separate. An opaque identity contains only an identifier and creation time. A practice relationship holds entered display name and optional recorded phone, email and birth date; none is identity proof. A create always issues a new identity and relationship. Matching names/household contacts never merge people, link other doctors' charts or create an Auth account. Client overposting identity/verification fields is rejected. There is no global identity discovery, patient login, hard-delete command or clinical note field.

Every directory/detail/duplicate query and command requires a current verified session, active working location within the named practice and explicit `patients.read` at that exact location. Writes additionally require `patients.write`; neither implies the other. Owners derive authority from stored practice ownership. Independently invited secretary grants remain per practice/location. The patient relationship belongs to the doctor practice, so another authorized working clinic can read it without moving person ownership. Creation and administrative history preserve their actual originating clinic/actor, including after clinic archive. All three public tables have RLS enabled and no client direct SELECT/DML grants; bounded authorized RPCs are the client surface.

Server search uses literal name/email matching and normalized phone digits within the authorized practice, with deterministic name/ID order, bounded pages and active/archived/all filters. Birth dates use the selected clinic's timezone for the latest valid date; entered data is not interpreted as a verified identity or clinical finding. Values render as text through shared UI.

Duplicate evidence includes only scoped matches (at most ten displayed, with total count). Its digest binds the verified actor/session, practice/location, record, normalized form and current matching IDs/versions. A newly discovered matching set requires explicit review and a second save. Under the practice lock the command rechecks current permissions, optimistic version and duplicate evidence; a newly introduced match requires a fresh review. Identity correction cannot overwrite a concurrent version. Actor-bound command receipts run before a create is mistaken for its own duplicate on an uncertain retry. Transport uncertainty preserves the exact key, values and reviewed evidence while the editor is open; changing material, closing, leaving or losing context discards that local intent.

Archive marks the relationship and appends attributed administrative activity/audit. The opaque identity, relationship and actual referencing activity remain intact; there is no cascade deletion. Archived records remain available only to currently authorized read contexts and cannot be silently corrected/reactivated. Future appointments/documents keep their own preservation and authorization checks in DOS-M1-012/014.

`packages/ui` owns the complete directory template, identity fields, duplicate-review display and shared edit/archive dialogs. `packages/ux` owns existing modal lifecycle. The Doctor app supplies typed DTOs, query/scope state, validation, command intent and props; no local presentation/CSS is added. Context changes discard search, pending rows, duplicate candidates and dialogs before accepting data for another practice/session. The table preserves its search control during query-error/retry states.
