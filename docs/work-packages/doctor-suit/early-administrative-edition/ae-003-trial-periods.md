# DOS-AE-003 one-time trial periods

This child follows PR373. It adds explicit trial allocation and retained subscriber-period history; quota/business-write enforcement and billing presentation follow in separate children. It does not complete DOS-AE-003, activate paid subscriptions, or close original clinical dependencies.

No account or period is seeded. A verified, admitted prospective owner may explicitly start a trial before clinic setup, using the current approved terms ID, configuration revision, internal document-version reference and stable command key. This avoids requiring a clinic before its first allowance can exist. Existing owner-enrollment authority rejects independent staff promotion; browser paid/role/duration/amount metadata is ignored.

The subscriber lock serializes allocation and rechecks actor admission after waiting. A shared configuration-row lock permits independent subscribers while keeping an offer replacement atomic. Exact retries return the original creation receipt; new keys cannot reset a previous trial, including after expiry. The client adapter sends only the declared acceptance/key fields and treats creation receipts separately from current period state.

Periods are append-only, scoped by a composite subscriber/period key, and must exactly match an approved positive trial duration and accepted document version. Trial days are exact UTC days across connection timezone/DST changes. Non-finite or unsupported transport dates fail atomically. The only supported period kind is trial; no paid activation path exists. Account suspension/resumption uses revision CAS and attributed immutable history and preserves original dates. Offer replacement does not rewrite a subscribed snapshot or reset its period.

The owner-scoped status projection returns unconfigured/trial/expired/scheduled/suspended state, original timestamps and original approved terms. Expired history remains readable. A previous subscriber who later becomes delegated can read their own retained financial history without creating a new account or receiving another practice's paid rights. Paid/live activation flags remain false. Reading status never subscribes a staff identity.
