# DOS-AE-003 trusted terms foundation

This child follows PR372 and implements the terms/identity foundation of DOS-AE-003-C01/C02. Subscription state, trial allocation, transactional quotas, expiry enforcement and billing UI remain subsequent bounded work. It does not complete DOS-AE-003 or the original M6 tasks.

The migration creates no offer versions. The single current-offer pointer starts null. Unknown prices, currency/precision, enabled monthly/yearly intervals, trial, staff/clinic allowances, over-limit behavior, renewal, grace, expiry, cancellation, refund and legal-document version stay unconfigured. There is no inherited Shop offer, default trial, free plan, unlimited allowance or implicit automatic charge.

Draft and approved term versions are append-only. Selecting a version requires complete approved data and an optimistic configuration revision; pointer history records the old/new version and database actor. Raw versions, approval references and configuration are protected by forced RLS and database-owner-only access. Browser and service API credentials cannot approve or select terms. Completeness checks treat SQL NULL as incomplete. An explicit zero is distinct from unknown; unlimited allowances require an explicit policy choice. The supported historical-access policy retains read access rather than deleting data. Both over-limit alternatives require an approved value; this foundation represents the policy and does not yet enforce it.

The authenticated read-only projection resolves subscriber identity from the verified actor and existing owner-enrollment policy. Staff membership and client metadata cannot create ownership or a SaaS subscriber. Existing owners who are independently delegated elsewhere retain their own subscriber practice; prospective owners receive no fabricated practice. Internal approval evidence is withheld. The public legal reference is an opaque internal version, never an arbitrary external URL. The typed decoder checks identity, integer money/precision, every configured policy and explicit quota kinds, and strips unprojected fields.

Commercial configuration alone leaves payment_route unconfigured, purchase_available false and live_activation false. There is no subscription/settlement mutation or commercial approval in this PR. Operator decisions and original clinical dependencies remain open. Synthetic values in tests are illustrative fixtures rolled back inside the owned database; they are not Doctor approval.
