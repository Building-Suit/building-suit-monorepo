## Implemented contract

Doctor owns a version `1.0` implementation of the existing newline-delimited HMAC-SHA-256 request/response protocol. It hashes exact UTF-8 body bytes, verifies with Web Crypto, binds source/target/environment/audience/key, checks the explicit key validity interval, verified pinned manifest, protocol/operation versions and configured timestamp/body/nonce policies. Unknown policy values have no defaults. Duplicate protocol headers, changed bytes/signatures, wrong keys/environments/audiences, unsupported capabilities and extra payload fields are rejected. It imports no other app implementation and uses no Shop identity, session, key, price, trial/paid period, receipt or history.

Only `adapter.capabilities.read`, `doctor.account.query` and `doctor.plan.query` can be represented in this synthetic read contract. Commands, account creation, owner invitation, impersonation and plan/operator activation are unsupported. Read selection contains only the target subscriber UUID; it accepts no email, password, role, arbitrary URL or endpoint. A trusted target reader must return an exact subscriber projection backed by a non-anonymous, email-confirmed Doctor Auth identity and stored practice ownership. Signed external actor/role metadata is attribution, not authority: the exact authority/subject pair and operation must match the independently configured target operator capability map. Product queries cannot return arbitrary patient/clinical payloads.

Successful responses and authenticated operator/target denials are signed over the protocol response fields, numeric status, exact request digest and exact response digest. Source verification still must reject unsigned errors and mismatched echoes as ambiguous outcomes. Provider/internal exceptions are normalized without propagating infrastructure text. The response always says operator grant unavailable, payment unconfirmed and live activation false; it cannot turn an operator action into payment evidence.

## Durable nonce and audit adapters

Two new public business tables force RLS and revoke raw privileges from anonymous, authenticated and service roles. Private security-invoker fixture/storage helpers consume the unique `(source binding, key ID, nonce)` receipt and append actor/binding/request/correlation/operation/digest/manifest/outcome audit. Both histories reject update/delete/truncate. Audit insertion requires an already consumed nonce with the exact request ID and rejects extra raw payload/signature fields. No client or service-role execution is granted to these storage helpers.

The protocol callback contract requires **a separate committed nonce transaction before domain reads**. A failed target read or lost response cannot unconsume it. Configuration and the signature window are revalidated after nonce persistence, so a changed/revoked binding or elapsed deadline cannot authorize a stale read. Query retries retain the logical request/correlation IDs with a fresh nonce; query reads create no account, grant, payment, session or entitlement mutation. Disabled commands do not have a fabricated idempotent success path.

The disposable PostgreSQL adapter proves the callback contract against real persisted rows and separate sessions: two simultaneous signed attempts yield one read/audit, a fresh-nonce retry adds attributed read audit, signed target denial retains its committed receipt, and a second database transaction waits on a duplicate nonce before returning denial. The test target reader selects the exact Doctor user ID and stored owner association. Fixtures use explicit synthetic operator/binding IDs and known in-memory test bytes; they create no deployed signing credential or actual source/target configuration.

## Closed operational boundary

`doctor_administration_readiness` and its strict application decoder report caller-scoped `unavailable`, target/signing `unconfigured`, live policy/operator approval `pending`, no capabilities and false operator-grant/payment/live flags. Actual disposable provider acceptance additionally verifies that this state does not acquire authority. No bridge HTTP endpoint, configuration loader, target binding, signing reference/material, source registration, live policy or operator permission is provisioned. The protocol module is a dependency-injected server contract; it cannot be enabled by browser data or by its test fixtures.

To progress beyond this foundation, the owner must supply genuine Doctor-specific environment/principal bindings, independent policy/evidence, signing custody and verified manifest/capability authorization through approved target/source server adapters. Operational loader/secret-store wiring, real source Auth/operator acceptance and account/grant command implementation require that approved scope and separate review. Operator grants must remain distinguishable from paid settlement, target identity must be independently verified, and there can be no email-match ownership or automatic email verification. The original clinical/legal/live gates remain pending.
