# Screen / State Catalogue

**Status:** Plan approved (2026-06-20) — state contract. **Login states all demonstrated in the prototype (A+B, 2026-06-21), awaiting user approval;** all other rows are contract only, nothing built.
**Source of truth:** UX §3 (View States), §2 (IA), §4 (Validation/Interaction). Each screen family below lists the states the prototype must demonstrate before approval.

## Universal states (apply to every screen family)

- **Dark mode** — every screen ships light + dark; primary action flips Navy (light) → Gold (dark). Sources: tokens `color.role`, dark/light mode guides.
- **Arabic RTL** — full mirrored layout, right-aligned text, mirrored directional icons, Arabic line-height +10–15%, logo artwork never flips. Sources: UX §4.10; Typography RTL rules.
- **Focus / keyboard** — 2px Premium Gold focus ring (offset); 44×44dp targets. Source: component guide; UX §4.1.
- **Reduced motion** — supported; shell/hero/scroll-linked motion remains active per UX §4.11.8.

Per-screen rows below capture **Ideal / Loading & Processing / Empty / Error & Restricted** specifics. Dark + RTL are required for each and are not repeated per row.

## Notes

- Every screen's **success** behavior follows UX §4.7 (toast for in-context mutations; close modal/drawer on success; redirect only on material context change).
- Every screen's **error** behavior follows UX §4.8 (one transparent refresh on expiry; keep input on network failure; never report false success).
- **Confirmation/destructive** rules per UX §4.9 apply to building creation after conflict, occupant replacement, member removal, leave building, join-code regeneration, billing deletion, finance writes, vote cast, vote close/cancel, issue close, and logout.
