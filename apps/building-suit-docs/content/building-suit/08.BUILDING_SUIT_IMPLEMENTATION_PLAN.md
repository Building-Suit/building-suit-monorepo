# Building Suit — Implementation Plan / Task Tracker

## 1. Purpose & how to read this tracker

This is the execution view of the approved documentation set. It converts the product, business, UX, architecture, data, API, and security specifications into:

- **Milestones** (§3) — the delivery spine.
- **Epics** (§4) — the PRD value themes (E1–E8).
- **Features & tasks** (§5) — work items with dependencies, priority, complexity, acceptance criteria, and linked sources.
- **Foundation / cross-cutting work** (§6) — the platform substrate every feature depends on.
- **Dependencies & critical path** (§7).
- **Definition of Done** (§8) and **acceptance-criteria traceability** (§9).
- **Gates, open decisions, and risks** (§10).
- **ID index** (§11).

Reading a task row: each row links back to its **source clause(s)**.

**GATED does not mean undefined.** A GATED item is fully specified by the source documents — its behavior and acceptance criteria already exist — but the sources place it behind an explicit activation condition. There are two kinds:

- **Activation-gated:** the source defines the behavior and priority, but external/compliance readiness must exist before activation. Paymob is activation-gated, starts from zero, and is the top engineering/business priority; its first release must include both resident-to-building payment collection and Building Suit SaaS subscription billing. Payout, wallet, custody, settlement, fee schedules/quotes, and licensing assumptions remain unactivated until Paymob, legal/compliance, finance operations, and engineering validation is complete.
- **Scope-gated (post-MVP):** the source explicitly removes it from the MVP. Service Provider functionality and Shop/Business/City Suit interfaces are not active MVP work. They activate only after a future decision reintroduces them.
- **Clarification-gated:** the source says "requires clarification from engineering" for a specific detail. The feature appears in the plan but the open detail is blocked until recorded in the originating document's Decision Log.

So Paymob and E8 are clear in the prior docs: *what* to build is defined (PRD §5.5, §5.9 acceptance criteria), and *when* is defined by readiness gates. GATED encodes that sequencing, nothing more.
