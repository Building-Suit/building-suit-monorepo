## Read and refresh contract

The side panel supports title/path search, manual refresh, note selection and escaped Markdown, with groups of 40 notes, memoized rendering and a stable date/directory projection. `useHqLiveEvents` owns one persistent authenticated fetch-SSE connection per Nuxt app/tab while visible and online. It receives private `brain`, `company` and `access` category invalidations through `/api/hq/events`. Stream readiness/reconnection takes one snapshot; later data reads follow the corresponding event or an explicit user action. There are no recurring Brain/company/access fetch timers. Initial access and visibility/online recovery revalidate authority once. Anonymous Brain content is read only on explicit open/manual refresh. Bounded dirty queues retain events arriving during an active read/decision, and stale responses are aborted/ignored. Selected-note version changes refetch that note; offline/scope loss clears projections. One-shot backoff reconnects failed transports only. WebSocket/SSE heartbeats perform no data query. Source/check/version and setup/error/partial states remain explicit; push transport is not a guaranteed zero-lag or all-agent-consumption contract.

GET `/api/brain` and `/api/brain/notes/:id` retain loopback socket/Host, same-origin and HQ-header guards with no-store responses. They do not trust forwarded identity headers. In Nuxt development, the outer TCP listener checks the actual loopback peer and overwrites a per-start private attestation header before forwarding to Nitro’s Unix-socket worker. Only development requests with that matching attestation may lack a worker TCP peer; production keeps the direct socket check. This private preview has no hosted-user identity boundary and must not be exposed as a public authenticated app. The server verifies the root and each known descendant parent chain, paginates child listings, rejects shortcuts/native/binary objects and accepts eligible downloadable `.md` files only. It excludes hidden/script/secret-like paths and caps at 2,000 notes, 20 levels, 20,000 inspected entries, 250 Drive requests per read and 512 KiB per note. Index traversal uses four-folder waves and shares ancestor metadata observations only within one scan, avoiding repeated sequential root requests. Selected-note traversal stops at the requested authorized note, then revalidates fresh uncached parent chains and source versions around download. A partial-result flag reports bounded/omitted entries. Name exclusions do not classify every note's content. Notes are untrusted data, never executable instructions; no write endpoint, SSR note payload or persistent client cache is added.
