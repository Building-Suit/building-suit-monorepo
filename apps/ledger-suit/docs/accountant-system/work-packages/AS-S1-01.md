# AS-S1-01 — دليل الأرقام ونموذج رحلة المراجعة

الحالة: `READY_FOR_REVIEW`؛ المرحلة ١ من الخطة §١٠؛ اليومية §٦ والقبول §١ و§٣. كُتبت خطة الحزمة قبل تعديل الكود، 2026-09-19.

## النتيجة وحدودها

اختبار حتمي لكل قيد وأرصدة ومجاميع المثال، ونموذج قراءة قابل للتشغيل: اليومية ← القيد ← حساب بمعرفه ← حركاته الاصطناعية ← نفس القيد ← نفس اليومية. النموذج لا يستخدم بيانات حقيقية أو صلاحيات إنتاج ولا يدّعي تشغيل الوحدات غير المكتملة.

داخل النطاق: وثائق الاستئناف والقرارات والتتبع؛ fixture بالوحدات الصغرى وBigInt مستقل عن حسابات الإنتاج؛ test fixture Nuxt مع طبقة UI الحالية؛ حالات تحميل/خطأ/إعادة محاولة/غير موجود/رفض؛ حفظ الفلاتر والتاريخ والترتيب والصفحة والتمرير والتركيز وملاحظة مراجعة غير محفوظة؛ عزل بيانات العرض عند تبديل منشأة/جلسة/حساب.

خارج النطاق: تعديل الحسابات المستوردة أو دلالات الترحيل/العكس/الموافقة؛ حساب تقارير إنتاج؛ SQL أو تغيير تاريخ ترحيلات؛ مخزون أو ذمم أو إقفال؛ تركيب النموذج في إنتاج؛ دمج أو نشر أو تجهيز موارد.

الاعتماديات: pnpm 10.33.0 وNode كما في .node-version؛ root lockfile؛ Chromium للاختبارات. اختبار النموذج والأرقام بلا backend. اختبارات الانحدار المالي تحتاج Ledger المحلي 60321 وقاعدة 60322 موثقة الملكية والتاريخ، ولا يُعاد ضبط قاعدة تخص عملًا آخر.

لا يحتاج هذا الدليل توقيع سياسة. قبول التكوين وانتقال المراحل ينتظر AS-D01–AS-D07. لا يوجد قبول محاسب مسجل في الوثائق الحالية.

- المستهلكون المشتركون: إعادة استخدام UI/UX/tokens دون تغيير ملفاتها؛ لا تعديل Shop أو docs app.

## القبول وخطة الفحص

- REF-01: عشرة قيود متوازنة منفردة؛ افتتاح 150000 لكل جانب، حركة 60000، أرصدة ختامية 165000؛ جميع الأرصدة المحددة في القبول §١.
- REF-02: ربح 2000، أصول صافية 148000 = التزامات 17000 + رأس مال ونتيجة 131000؛ دون إقفال.
- REF-03: نقد 100000 → 83000؛ تشغيل -5000، استثمار -12000، تمويل 0؛ لا تدفق خارجي للتحويل والإهلاك.
- JR-01 (معرف اختبار فقط، ليس حزمة UI قديمة): تنقل واحد وعودة بنفس القيد والسياق وfocus؛ back/close والإلغاء أثناء تحميل.
- JR-02: حالات النجاح والتحميل والفشل/إعادة المحاولة والفارغ/غير موجود/رفض؛ بيانات أخرى متأخرة لا تعود بعد تغيير النطاق.
- JR-03: أسماء اصطناعية مستقلة en/ar، LTR/RTL وlight/dark و390px؛ لا تغيير الأسماء المخصصة والأكواد والعملات؛ صور تحت docs/evidence/as-s1-01.
- عزل النموذج: لا طلبات Supabase أو كتابة مالية؛ بناء Ledger المعتاد لا يحتوي route أو نص النموذج. الرابط المحلي والتحديث يبدآن مراجعة جديدة بوضوح؛ لا ادعاء حفظ المسودات عبر تحديث الصفحة.

الأوامر المخططة: `pnpm check`؛ `pnpm test`؛ Ledger lint/typecheck/build؛ `pnpm --filter @building-suit/ledger-suit test:reference`؛ `pnpm --filter @building-suit/ledger-suit test:review`؛ إعداد typecheck للنموذج؛ SQL وaccounts/core-finance إذا ثبتت سلامة القاعدة المحلية.

## التشغيل والمراجعة المحلية

من جذر worktree هذه الحزمة، باستخدام root lockfile:

```sh
pnpm install --frozen-lockfile
pnpm --filter @building-suit/ledger-suit test:reference
pnpm --filter @building-suit/ledger-suit review:dev
```

افتح `http://127.0.0.1:3216/`. اختر اللغة والمظهر ومنشأة المثال وحالة الاستجابة. اكتب ملاحظة مراجعة، غيّر التاريخ والبحث والترتيب والصفحة، وافتح رقم قيد ثم حسابه ثم عد. اختيار منشأة أخرى أو إنهاء جلسة المثال يمسح النطاق والملاحظة. لا مفتاح أو قاعدة مطلوبة؛ البيانات اصطناعية، واسم البنك المخصص يبقى كما أدخله المراجع.

للفحص الآلي أغلق خادم المعاينة الذي شغلته أولًا؛ Playwright يرفض إعادة استعمال خادم آخر على نفس المنفذ:

```sh
pnpm --filter @building-suit/ledger-suit exec nuxt prepare tests/review
pnpm --filter @building-suit/ledger-suit review:typecheck
pnpm --filter @building-suit/ledger-suit test:review
```

الصور في [docs/evidence/as-s1-01](../../evidence/as-s1-01/)؛ تأخذها Playwright من بيانات اصطناعية فقط. يثبت اختبار التمرير قيمة أكبر من صفر عند ارتفاع 560px ثم يعيد التقاط حالة الهاتف بارتفاع 844px. Escape/زر الرجوع من الحساب يعيدان القيد، ومن القيد يعيدان اليومية والتركيز. الرابط الجذري والتحديث يبدآن مراجعة جديدة معلنة؛ deep links للتفاصيل وحفظ المسودات عبر التحديث من نطاق AS-S3-01، وليسا قدرة مثبتة هنا.

## حدود النشر والقرارات

حالة التسليم: محلي فقط إلى أن تتحقق شروط نشر فرع المراجعة. تكوين Vercel المتعقب يمنع feature branches، لكن قراءة get_project من connector فشلت مرتين بخطأ عقد idOrName رغم استخدام schema الأداة؛ إعدادات المشروع الحية غير متحققة. قراءة Supabase المحدودة أثبتت ref `yqculoltqsyfastmihmu` في منظمة Ledger وربط default branch بـstg وحالة سليمة؛ list_branches لا يثبت أن Automatic branching مغلق. أدوات المتصفح اللازمة لقراءة dashboard غير متاحة في الجلسة بعد discovery. لم يُستنتج الإغلاق من عدم وجود preview، ولم تتغير إعدادات أي مزود.

لذلك لم يُدفع الفرع ولم يُنشأ PR يمكن أن يطلق تكاملًا. يُسلّم commit محلي وملف PR جاهز وbundle وفق brief. قبل نشره: تحقق read-only من Automatic branching وإعداد Root Directory/filter الفعلي؛ أعد preflight واختر هدف المراجعة الحي ثم agent:pr-check بعد الإنشاء. هذه الخطوة تخص نشر فرع المراجعة المصرح به فقط؛ لا تعني دمجًا أو نشر تطبيق أو تغيير إعدادات. D01–07 وUAT تظل معلقة، ولا تمنع مراجعة النموذج محليًا.
