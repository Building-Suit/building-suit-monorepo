# AS-S2-01B — تصنيف عرض المركز المالي بتاريخ سريان

الحالة `READY_FOR_REVIEW`، 2026-09-19. حزمة محدودة من المرحلة ٢، تحت تفويض المؤسس AS-E02. الخطة مثبتة قبل تنفيذ الميزة؛ لا انتظار موافقة محاسب جديدة.

## الأساس والهدف

الفرع `codex/ledger-suit/statement-classification` من رأس PR #7 `cea53f806102a30a3d7ed72776138bbac2c176b9`. stg المتحقق `d7eb4c9cdfb43e1b9df72d9cf6070f74bbd40ce0`. #8 اندمج في #7؛ #9/#10 أغلقا كتكرار والعمل محفوظ في #7، الذي لم يندمج في stg عند البدء. worktree Shop sales مستقل عند stg وبه تعديلات غير ملتزمة؛ لا تُنسخ ولا تتغير. الاختيار المتعمد للأب هو أحدث مرشح Ledger الملتزم الذي يحوي متطلبات الطبيعة والتجميعي، وليس checkpoint Shop الخالي من هذه المتطلبات.

المستخدم يحدد بند عرض الحساب وتاريخ سريانه وسبب الاختيار. التقرير يستخدم التصنيف الساري في تاريخ التقرير ويبين الحسابات غير المصنفة، دون تغيير طبيعة الحساب أو قيم القيود. الحساب المخفِّض يحتفظ بإشارته السالبة.

## قرارات وحدود هذه الشريحة

- المركز المالي فقط: أصول متداولة، ممتلكات ومعدات، أصول غير متداولة أخرى، التزامات متداولة/غير متداولة، حقوق ملكية. لا تصنيف تلقائي من الاسم أو نوع القرض، ولا تقسيم جزئي لرصيد الحساب.
- سجل إضافي غير قابل للمحو أو التعديل. سريان جديد بعد يوم المنشأة الحالي وبعد تاريخ القفل، وليس بأثر رجعي. التصحيح بتاريخ مستقبلي مماثل يسجل نسخة جديدة مع سبب؛ التاريخ الأقدم من آخر تاريخ مقرر مرفوض. التقرير السابق واليوم الحالي لا يعاد تصنيفهما خفية.
- السبب مطلوب ويسجل أساس الاختيار (دورة التشغيل/الاستحقاق/قيود النقد/حق تأجيل السداد/شروط التمويل بحسب الحالة). استنتاج التصنيف الآلي والحقول المهيكلة التفصيلية وإعادة العرض التاريخية المعتمدة مؤجلة.
- كتابة واحدة مفوضة وذرية مع صلاحية accounts.update والاشتراك، قفل الحساب، مقارنة نسخة متوقعة، ومفتاح طلب يمنع تكرار الحفظ أو تغيير حمولة الطلب نفسه. لا صلاحية تعديل جدول مباشرة للعميل.
- يحتفظ الحساب الموجود بلا تصنيف صريح ببند غير مصنف داخل نوعه، ولا backfill تخميني. التقرير القديم وCSV القديم يظلان متوافقين؛ التقرير المصنف وCSV الموافق له يضافان بعقود واضحة ومبالغ نصية دقيقة.
- رفض حساب group، نوع revenue/expense، حساب مؤرشف عند جدولة تغيير جديد، الربط بين المنشآت، والتواريخ غير الصالحة. القراءة التاريخية للمؤرشف محفوظة. لا تغيير نوع الحساب بعد إنشاء سجل تصنيف.
- واجهة en/ar في الحسابات لعرض السجل وجدولة التصنيف، مع controllers المشتركة وحماية dirty/pending وتبديل المستخدم/المنشأة. المركز المالي يعلن تاريخ التصنيف ويصدر نفس النسخة والقيم.

لا تغيير قيود أو أرصدة أو حصص أو فترات قفل موجودة. لا ضريبة/مخزون/مراقبة أو إعادة عرض تاريخية أو ترحيل مستضاف. ق٠٨ تقدم جزئي: صون التصنيف السابق؛ إعادة العرض المعتمدة ما زالت لاحقة. موافقة التنفيذ ليست UAT.

## خطة التحقق

1. Migration أمامي جديد وتوليد types من المصدر، مع حفظ 80 بصمة تاريخية.
2. مشروع disposable مستقل للحزمة، API 64321 وDB 64322 وapp 3230؛ لا لمس 60321/63321 أو قواعد المهام الأخرى. تطابق source/history قبل الاختبارات.
3. pgTAP لعزل RLS/grants، roles/subscription، idempotency/conflict/concurrency، قفل الفترة، رفض الأثر الرجعي، النسخ المستقبلية، الأرصدة/contra/الأرشيف، CSV، وتوافق التقرير السابق؛ تجربة قبل/بعد مع تاريخ مستخدم.
4. وحدات لحساب المجاميع النصية، واختبارات متصفح بقاعدة حقيقية en/ar، تاريخا تقرير، حفظ/تكرار/أخطاء، history/read-only وتبديل النطاق والشاشة الضيقة.
5. check/test، Ledger lint/typecheck/build، مجموعة SQL الكاملة، browser regression للحسابات والطبيعة والتجميعي وcore؛ advisors وDB lint. تسجيل PASS/FAIL/NOT_RUN وأرقام فعلية فقط.
6. تحديث status/decisions/evidence/traceability وPR تابع للمرشح النشط بعد فحص GitHub والمزود. لا merge أو deployment؛ توقف للمراجعة.

## التشغيل والتوقف للمراجعة

من الحسابات اختر «العرض في القوائم» لحساب ترحيل من أصل/التزام/حقوق ملكية، ثم البند والتاريخ المستقبلي والسبب. راجع التاريخ السابق واللاحق في المركز المالي وCSV. القارئ يعرض السجل دون كتابة. التاريخ يتبع يوم المنشأة والقفل، ولا توجد بوابة محاسب جديدة تحت AS-E02.

عند نشر مصرح لاحقًا: تحقق هوية المشروع وسجل migrations وsnapshot أولًا، ثم migration الجديد بعد nature/groups وقبل واجهة RPC الجديدة. لا drop/reverse للسجل عند تراجع الواجهة؛ يمكن العودة للواجهة والعقود القديمة مع إبقاء السجل والحراس. اختبار حجم بيانات عميل وخطة الاستعادة المستضافة وUAT وdeployment لم تنفذ هنا.

الحزمة مكتملة تقنيًا للمراجعة، وق٠٨ جزئي فقط. لا مانع موافقة محاسب للتنفيذ. لا دمج PR أو نشر تطبيق أو SQL مستضاف بهذه المهمة. عند الاستئناف التالي: preflight حي ثم حزمة محدودة لعرض قائمة النتيجة المؤرخ تحت AS-S2-01، قبل ادعاء اكتمال تصنيف القوائم؛ المراقبة/التقسيم الجزئي/إعادة العرض المعتمدة ما زالت لاحقة.
