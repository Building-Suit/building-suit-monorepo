# Shop Suit

Root rules apply. Routes and product orchestration are under `app/pages`; tenancy and plan adapters under `app/composables`; RPC contracts under `app/types`.

- Before every task, run the root `pnpm agent:preflight`. Use short-lived `codex/shop-suit/*` feature branches, keep fixes on their open PR, and follow `docs/shared/git-workflow.md` for stacks, parallel work and manual GitHub merges. Shop may have one active root PR into `stg`; Shop children target only an open Shop parent.
- Read `packages/ui/AGENTS.md` before presentation changes. Routes consume registered complete page templates from `packages/ui`; reusable interaction controllers belong in `packages/ux`. Shop owns business/data/permission logic, typed values/content and semantic commands.
- Follow [UI-D01 component selection](docs/ui-foundation.md): PrimeVue 4.x is the interactive foundation, composed through `@building-suit/ui` wrappers. Native semantic controls and PrimeVue composition belong inside `packages/ui`, including product-specific forms. Use `BsButton`, `BsForm` and virtualized `BsSelect` for the standardized operational patterns; history uses server pagination. Do not compose forms, tables, overlays or pickers in Shop routes. `pnpm check` enforces the foundation boundary.
- Preserve shop/portal/profile distinctions, membership and subscription checks. Treat display metadata as untrusted input.
- Catalog, inventory and expense mutations use authorized atomic RPCs. Preserve request idempotency, FIFO, closed-period and archival/void rules.
- Keep amount units explicit: Shop decimal amounts and Ledger minor units are different contracts. Shared presentation must not silently convert business arithmetic.
- Verify the implemented feature against its current product requirements and backend. Historical rebuild plans are context, not an automatic task queue.
- Database SQL, local seeds and tests are owned by this app’s `supabase/` directory. Select it from the root with `pnpm db shop-suit <command>`. Business objects and client RPCs use `public`; this product has its own production/staging pair and Auth sessions. Keep the portal key `shop-crm` unchanged.

Atomic template ownership: each Suit route renders exactly one complete, explicitly exported page-level template from `packages/ui`, using typed neutral view models, controlled form values, content and semantic commands. Shared UI owns all presentation, including unique product-specific compositions. Suit scripts retain business rules, authorized data access and configuration. Shared interaction controllers live in `packages/ux`. Suit routes cannot supply child composition, scoped slots, component/render factories, VNodes or untyped state bags. Layout adapters supply only typed shell configuration and one direct unscoped route outlet. Do not add app-local Vue components or migration debt allowances.
