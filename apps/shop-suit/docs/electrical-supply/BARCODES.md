# Verified weight labels

SS-ELEC-504 extends ordinary POS scanning. Literal product, package and physical-reel barcodes are looked up first and keep their existing meaning. Only the following verified subset is decoded as weight: AI01 with a checksum-valid variable-measure GTIN-14 starting with 9, immediately followed by AI3100 through 3105 and six numeric digits of net kilograms. Raw GS1 element strings, the GS1-128 `]C1` AIM carrier prefix, and compact parenthesized human-readable representations are accepted. Extra fields, reversed fields, unsupported carriers, zero weight and unknown formats are rejected or remain ordinary unknown barcodes.

The GS1 application-identifier dataset was read from <https://ref.gs1.org/ai/GS1_Application_Identifiers.jsonld> on 2026-10-25, SHA256 `5d51e7a867596f252a5776ae69a625eca5b08d1c247c05945d922c7b2f68108e`. Its supported 310n identifiers are 3100..3105. This is a deliberately bounded implementation, not a decoder for every valid GS1 element-string combination. See also <https://www.gs1.org/standards/gs1-logistic-label-guideline/1-3>. National restricted-circulation 13-digit formats vary, including price and mass variants; no Egyptian prefix or encoded price is guessed. Supporting a merchant's additional format requires its authoritative specification and test labels.

Initial variable-weight capture requires a connection to verify the current primary GTIN, active measured mass product, location, POS authority and exact increment. Kilograms convert only to the product's approved canonical mass unit. Existing fixed-barcode and manual measured sales retain their offline paths. Offline unknown weight labels offer connection or manual entry; there is no inferred cached mapping.

Each capture gets its own cart line and UUID, preserves its original label and locks quantity/unit editing. Remove and rescan to change the weight. Canonical stock checks include other cart lines for that SKU across sale units. The existing numeric cart widget accepts only a checked exact decimal round trip; all conversion and capacity arithmetic uses decimal integers. No price comes from the label.

The private server validator independently parses the original label and checks identity, reserved literal namespaces, canonical quantity and increment during ordinary draft save and locked issuance repricing. Issued snapshots retain the original label, GTIN, net kilograms and canonical quantity. A changed product barcode rejects a still-draft capture without partial issuance. Existing accepted-order agreements retain their frozen quantities and prices. FIFO, tax, payment idempotency, partial returns and original cost authority continue through the existing financial commands.

Local evidence: 116 migrations, 22 selected SQL suites, both measured/physical journeys and eight inherited races pass together. Parser/checksum/unit/stock and existing POS units pass 8/8; Shop typecheck and build pass. Final built bilingual browser, root, release and native checks remain in progress. Hardware labels/scanners, real merchant acceptance, native Arabic review and hosted rollout remain separate gates.
