# Selective public catalog — SS-WEB-CATALOG-001

The public catalog is an explicit owner-curated disclosure layer, separate from operational products/services. No migration backfill publishes an existing item. Internal active/archive flags, names, prices, inventory and service scheduling are never mutated by catalog commands. The existing registered business settings template contains the shared catalog organism; no new route or storefront is added.

Owners edit public name/description, an independent optional raster image, display order and Show price. A suggested operational name is shown only in the owner editor; descriptions and images are never copied from operational records. Saving details creates a private entry, or retains an existing entry's publication flag. Publishing is a separate explicit owner action. Unpublish retains configuration and works during a read-only subscription. Non-owner settings managers cannot read or change this owner-only disclosure configuration.

Tenant-scoped composite foreign keys protect source references and audit ownership. Every write rechecks owner identity and existing Shop write authorization; revocation requires ownership without the paid-write gate. Shop-row locking serializes publication/readiness changes with PROFILE commands. Private RLS tables have no direct browser/service-role grants. Actor, action, entry and time are audited. Public images reuse the shared bounded raster decoder and server validator (PNG/JPEG/WebP, 128 KiB, 2048 pixels per dimension); no operational Storage URL/path or external image URL is exposed.

`shop_private.website_catalog_readiness` now reports actual eligible owner-published items with `integration: ready`. Only published entries whose source remains active count. A displayed price must be a valid nonnegative operational amount; otherwise the entry is not eligible. A hidden-price service may have no operational price. PROFILE still requires its other fields, a visible active location and explicit owner opt-in. Catalog edits never publish a website. The source adapter reads product `sale_price` and service `base_sale_price` without discount/financial arithmetic.

`shop_website_public_catalog(slug, page)` is an allowlisted read contract for PUBLIC, not storefront rendering. It checks the current published PROFILE, Shop state, owner opt-in and live readiness on every read. It returns at most 20 entries per page, stable display order plus public-token tie-break, canonical slug and current total. Each entry contains only a newly minted `publicId`, kind, public name/description, optional explicit image, display order and `priceMode`. `price` and `currency` exist only for `priceMode: shown`; both keys are absent for `contact`. PUBLIC must render the latter as translated Contact for price, as the private preview already does. Source IDs, Shop/portal/member IDs, costs, stock quantities, FIFO, supplier information, scheduling/staff, internal notes, SKUs and barcodes are absent.

Archiving/inactivating a source hides it immediately while retaining publication configuration. Restoring a still-published source makes it eligible again. Explicitly unpublishing an inactive entry prevents restoration from republishing it. Removing the last eligible item immediately makes PROFILE/public catalog reads unavailable. Immediate site Unpublish always returns the public catalog to null, regardless of item flags; later catalog edits cannot undo site Unpublish.

There is no materialized public cache, signed operational asset URL or HTTP storefront cache. Private query keys contain environment, portal, actor, Shop, search and page. Writes clear all cached searches/pages for that exact scope and refresh PROFILE readiness; context/session changes clear editors and late results. PUBLIC must preserve uncached/no-store host responses and the existing early tenant-host boundary rather than caching anonymous RPC payloads past revocation.

No cart, checkout, order, reservation, payment, booking or staff-workload feature is included. No actual customer site is published by this task. Wildcard hosts continue returning the SLUG task's fail-closed response until SS-WEB-PUBLIC-001 supplies rendering. Forward migration deployment belongs to the normal future CI/integration flow; no hosted data write, manual deployment or provider configuration is performed here.
